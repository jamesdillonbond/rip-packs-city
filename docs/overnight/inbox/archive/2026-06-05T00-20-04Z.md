## NEW candidate — AF1 (HIGH · operator/CC or night-pass DB): `rpc-tracked-fmv-confidence` artifact broken — backing view times out

- **Title:** Optimize `v_tracked_wallet_fmv_confidence` so the artifact stops timing out on open.
- **Source:** artifact validation (Section 1b) — `rpc-tracked-fmv-confidence` / query `SELECT collection, confidence, held_editions FROM public.v_tracked_wallet_fmv_confidence`; timed out 2× this run; DB otherwise responsive (all other sweep queries fast, incl. a `DISTINCT ON` over partitioned `fmv_snapshots` filtered by collection_id).
- **Root cause (from `pg_get_viewdef`):** the `latest` CTE does `SELECT DISTINCT ON (fs.edition_id) fs.edition_id, fs.confidence FROM fmv_snapshots fs JOIN held h_1 ON h_1.edition_id = fs.edition_id ORDER BY fs.edition_id, fs.computed_at DESC` — i.e. it joins **all** of partitioned `fmv_snapshots` (full daily history) to the held-edition set with **no `collection_id` filter**, so the planner can't prune partitions and sorts the entire snapshot history for every held edition. The cheap health-sweep variant works precisely because it filters `collection_id IN (...)`.
- **Blast radius:** the one artifact only (grep: 0 references in `app/`/`lib/`; not a production route). User-perceived FMV is unaffected; this is an internal Cowork analysis dashboard.
- **Risk read:** LOW–MED. Fix is a `CREATE OR REPLACE VIEW` (view-only, no data, mount-independent — the night pass's normal lane), reversible by restoring the current body. Same optimization pattern already used twice in-repo (the AllDay batched-RPC `LATERAL … ORDER BY computed_at DESC LIMIT 1`; the `v_moments_needing_hydration` materialized-CTE fix).
- **Suggested action (night pass to craft + subagent-verify, not me):** rewrite the `latest` CTE to a per-held-edition index seek instead of a full-history sort — e.g. `LEFT JOIN LATERAL (SELECT confidence FROM fmv_snapshots fs WHERE fs.edition_id = h.edition_id ORDER BY computed_at DESC LIMIT 1) l ON true`, and/or push `collection_id` into the snapshot scan to enable partition pruning. **Preserve `security_invoker` + existing grants on CREATE OR REPLACE** (grant-reset footgun per the `rpc-migration` skill — check `\dp`/reloptions before replacing). Verify post-apply: the exact artifact query returns < the statement_timeout. **Revert (current body):**
  ```sql
  CREATE OR REPLACE VIEW public.v_tracked_wallet_fmv_confidence AS
   WITH tracked AS (SELECT DISTINCT seeded_wallets.wallet_address FROM seeded_wallets WHERE seeded_wallets.is_active),
   held AS (SELECT DISTINCT e.id AS edition_id, e.collection_id FROM wallet_moments_cache wmc JOIN tracked t ON t.wallet_address = wmc.wallet_address JOIN editions e ON e.external_id::text = wmc.edition_key AND e.collection_id = wmc.collection_id),
   latest AS (SELECT DISTINCT ON (fs.edition_id) fs.edition_id, fs.confidence FROM fmv_snapshots fs JOIN held h_1 ON h_1.edition_id = fs.edition_id ORDER BY fs.edition_id, fs.computed_at DESC)
   SELECT c.slug AS collection, COALESCE(l.confidence::text,'NO_SNAPSHOT') AS confidence, count(*)::integer AS held_editions FROM held h JOIN collections c ON c.id = h.collection_id LEFT JOIN latest l ON l.edition_id = h.edition_id GROUP BY c.slug, COALESCE(l.confidence::text,'NO_SNAPSHOT');
  ```
