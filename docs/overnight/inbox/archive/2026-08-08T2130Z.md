## 1. `sync-nba-projections` — OPERATOR ACTION (secret), then deploy

**The "NBA offseason / seasonal, not a defect" explanation is WRONG** and had been parked in project memory, which is why it survived. Both the memory note and an independent operator hypothesis reached for it on 2026-08-08. The run payload refutes it.

Three consecutive runs (`pipeline_runs.extra`, 08-08 09:07Z / 12:07Z / 18:07Z — 2:07 / 5:07 / 11:07 AM PT), byte-identical:

```
rolling_status: 401   rolling_error: "HTTP_401: unauthorized"   rolling_upstream_status: null
dk_status:      401   dk_error:      "HTTP_401: unauthorized"
espn_status:    403   espn_error:    "espn_HTTP_403"
```

`rolling` and `dk` both route through `rpc-sports-proxy`. **`rolling_upstream_status` is null**, so the request died at the worker's auth gate and never reached cdn.nba.com — not an upstream outage. `workers/sports-proxy/index.ts:970-972` returns exactly `jsonResponse({error:"unauthorized"}, 401)` when `X-Proxy-Secret !== env.PROXY_SECRET`; the logged string matches verbatim.

The edge fn sends `Deno.env.get("SPORTS_PROXY_SECRET")` as the `X-Proxy-Secret` header (`index.ts:399`); the worker compares it to its own `PROXY_SECRET`. One side was rotated without the other.

**Corroboration that this is sports-proxy alone, not a global rotation:** `topshot-moments-hydrator` ran **78/78 ok** and `topshot-listing-cache` **54/54 ok** on 08-08. Both authenticate to `topshot-proxy` with the shared secret. `workers/sports-proxy/index.ts:30-32` says to reuse topshot-proxy's value "so RPC env stays single-secret" — so sports-proxy's copy drifted off the shared value.

**Operator fix (never read or echo either value):** re-put the Supabase edge secret `SPORTS_PROXY_SECRET` to match the worker's `PROXY_SECRET`, or `wrangler secret put PROXY_SECRET --name rpc-sports-proxy`. Confirm by watching the next tick's `rolling_status` change off 401.

ESPN's 403 is real and separate (direct call, no proxy, no shared secret) but it is only tier 3 — fixing tiers 1+2 restores the pipeline.

## 2. The second, layered bug — staged in the repo, ⚠ NOT deployed

**Fixing the secret alone sends this arm straight back to red**, because the offseason part is also true: `nba_games` holds 46 rows, **0 future games**, last game 2026-08-04.

`supabase/functions/sync-nba-projections/index.ts` hard-fails on `chosenGames.length === 0 && scraped.length === 0` **without consulting `rolling.ok` / `dk.ok` / `espn.ok`**, so it cannot distinguish "every upstream broke" from "every upstream answered cleanly and there is no slate." Once the secret is fixed, a legitimately empty offseason slate still logs `ok:false, all_upstreams_failed`.

**Staged change (in the repo, unpushed by this session — Cowork has no push credential):**

- New `attemptedAllOk = rolling.ok && (!dk || dk.ok) && (!espn || espn.ok)` — `dk`/`espn` are only attempted when the tier above degrades, so an un-attempted tier must not count against the verdict.
- That block now logs `ok: attemptedAllOk`, `error: attemptedAllOk ? null : "all_upstreams_failed"`, and adds `reason` (`no_slate` | `all_upstreams_failed`) plus `rolling_ok` / `dk_ok` / `espn_ok` to `extra`.
- `FUNCTION_VERSION` 8 → 9.

**Safety property: the change is a provable no-op while the secret is broken.** Today `rolling.ok === false`, so `attemptedAllOk` is false and behaviour is byte-identical to now. It only changes anything once the upstreams answer cleanly — i.e. after the secret fix.

`deno check --config supabase/functions/deno.json supabase/functions/sync-nba-projections/index.ts` → **exit 0** (run in the cloud sandbox; the same `--config` invocation the blocking `edge-deno` CI job uses).

### ⚠ Two reasons this was NOT auto-deployed

1. **Prod is a version behind the repo.** Deployed `sync-nba-projections` is `FUNCTION_VERSION = 7`; the repo was already at `8`. The repo's v8 adds an ESPN **roster-stub fallback tier** (`ESPN_ROSTER_SOURCE` / `espn-roster-stub`, position-based placeholder projections) that **has never executed in production**. So deploying is really shipping *two* changes.

   **Audited — the deploy is safe NOW, and this is a dated follow-up rather than a blocker.** The tier is gated on `if (players.length === 0 && games.length > 0)` (`index.ts:640`). With **0 future games** ESPN returns no events, so `games.length === 0` and the tier is **structurally dormant**. It cannot fire in the offseason no matter what the secret does.

   ⚠ **It WILL fire on the first real slate**, and the audit is owed before then, not before the deploy. When it fires it emits a placeholder row for *every rostered player* (~16 teams × ~17 ≈ 270 rows) with a fabricated `proj_fp_dk` from `placeholderFpFromPosition` (C 22 / G 20 / F 18 / else 12) and every real stat field null — and `resolveOrInsertPlayers` step 3 will **auto-INSERT `nba_players` rows** for unknown bench/two-way names, a permanent catalog write triggered by a fallback tier. It is honestly tagged (`source: espn-roster-stub`, `projection_method: espn-roster-position-stub`, confidence LOW) and the code comment says the optimizer UI should render a "PROJECTIONS UPDATING" banner when this tier is active — **verify that banner actually exists** before the season opener, or `/nba/fast-break` will rank players by a position constant with no visible disclosure. That is the fabricated-data-landmine class.
2. **MCP `deploy_edge_function` resets `verify_jwt` → true**, which 401s the cron trigger (this fn authenticates with an `INGEST_SECRET_TOKEN` Bearer, and is currently `verify_jwt: false`). A deploy therefore requires a dashboard toggle afterwards: Edge Functions → sync-nba-projections → Settings → **Verify JWT with legacy secret → OFF** → Save, then confirm `verify_jwt:false` via `list_edge_functions`. The page renders stale on first load — F5 and wait ~8s before clicking.

**Suggested order:** fix the secret → confirm 401s stop → audit the v8 roster-stub tier → deploy v9 → re-toggle verify_jwt → confirm the next tick logs `ok:true reason:"no_slate"` (correct for the offseason) rather than `all_upstreams_failed`.
