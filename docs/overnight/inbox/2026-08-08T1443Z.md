## Head start (profile these — hypotheses, VERIFY with EXPLAIN (ANALYZE, BUFFERS) before shipping anything)
Table sizes: `sales` ~269K (year-partitioned) · `wmc` ~2.1M · `editions` ~31K · `fmv_snapshots` ~296K.

- **`mv_topshot_misattrib_candidates`** = `set_a ∪ set_b ∪ set_c`:
  - `set_a`: `sales JOIN editions` WHERE TS collection AND `external_id !~ '^[0-9]+:[0-9]+(::[0-9]+)?$'` — a regex filter
    over `editions.external_id` (non-canonical / UUID-pair keys).
  - `set_b` via `collide_groups`: `sales GROUP BY edition_id, serial_number HAVING count(DISTINCT nft_id) > 1`, then
    `sales JOIN collide_groups` — the heavy leg (full TS-sales aggregation + a re-scan join).
  - `set_c`: small audit table.
  - MV has a unique index (`…_nft_id_uq`) so CONCURRENTLY works. Likely lever: a **partial covering index** on
    `sales (edition_id, serial_number, nft_id) WHERE collection_id = <TS> AND serial_number > 0 AND nft_id IS NOT NULL`
    to serve `collide_groups` + `set_b` without a full partitioned scan. Confirm against the EXPLAIN first.
- **`v_fmv_thin_sale_ask_disclosure`**: the `s90` CTE (`MATERIALIZED`) does per-edition `percentile_cont(0.5/0.9)` over
  `sales` WHERE `collection_id <> pinnacle AND sold_at >= now()-90d` — ordered-set aggregates are the expensive part.
  Likely lever: a **partial index** on `sales (edition_id, sold_at) WHERE price_usd > 0.10` (or `(sold_at) WHERE …`) to
  cut the 90d scan feeding the percentiles. Verify.

## Decision rule for the night pass
- If EXPLAIN confirms a **`CREATE INDEX CONCURRENTLY`** on a `sales` predicate is the bottleneck fix → that is
  non-blocking, non-destructive, and reversible (`DROP INDEX CONCURRENTLY`), so it fits the ≤4-low-risk-changes lane.
  Ship ONE index at a time, then **force the refresh** and verify it completes under the timeout and `hrs_since_success`
  resets (query `cron.job_run_details`), and that the MV/cache row count stays sane.
- **Do NOT** raise `statement_timeout` (misattrib already 600s — masks, doesn't fix).
- **Do NOT** touch the misattribution REMAP logic (`remap_topshot_*` — data-integrity, pinned, off-limits). This is
  purely the MV *refresh performance*, not the detector's correctness.
- If the only real fix is a **structural refresh rewrite** (incremental / partition-pruned / non-CONCURRENTLY window) →
  that is higher-risk; **queue for operator** with the EXPLAIN attached rather than shipping it blind.
