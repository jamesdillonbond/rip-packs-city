End-to-end RPC: **9,664ms → 124ms (~78× faster)**. Migrations: `audit_20260518_unmapped_sales_sold_at_unresolved_idx` + `audit_20260518_rewrite_get_unmapped_resolver_targets`. Watch `allday-unmapped-resolver` pipeline_runs at `:00 / :20 / :40 UTC` — first post-deploy tick should go green.

**Action — RLS disabled tables (CRITICAL).** These tables are part of the `marketplace_offers` partitioned hierarchy. The parent (`public.marketplace_offers`) has RLS on, but the 2023/2024/2025 historical partitions and the `_default` catchall do not — meaning queries that route through PostgREST against the partitioned parent or the partitions directly will return rows unfiltered. Combined row count of the unprotected partitions: 493,087 rows.

```sql
ALTER TABLE public.marketplace_offers_2023 ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.marketplace_offers_2024 ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.marketplace_offers_2025 ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.marketplace_offers_default ENABLE ROW LEVEL SECURITY;
```

Note: enabling RLS without a policy will block all access (including service_role queries via PostgREST, though direct `service_role` JWT calls bypass RLS). If this data should be read-only public, add a permissive `FOR SELECT USING (true)` policy to the parent and let it inherit.

**Action — SECURITY DEFINER RPC sprawl.** 296 SECDEF functions exist in `public`, and 50 of them are reachable via PostgREST from the `anon` (18) or `authenticated` (32) roles. Most are intentional read-only RPCs (`get_top_deals`, `get_moment_detail`, `get_pack_lifecycle`, etc.) but each one effectively bypasses RLS. Worth a one-time audit of the anon-callable list to confirm each is safe to expose to unauthenticated traffic:

`check_email_allowed`, `get_allday_sniper_deals`, `get_insider_signals_top_n`, `get_moment_detail`, `get_pack_for_simulator`, `get_pack_lifecycle`, `get_top_deals`, `get_trophy_slab_data_by_username`, `get_wallet_pack_history`, `get_wallet_pack_summary`, `mcp_compute_pack_ev`, `mcp_find_set_completion`, `mcp_get_badge_data`, `mcp_get_fmv`, `optimize_fast_break_lineup`, `pack_purchases_set_is_primary_drop`, `resolve_moment_id`, `submit_allow_list_request`.

`check_email_allowed` is the one to inspect first — it can be probed to enumerate the allow-list. `pack_purchases_set_is_primary_drop` is a **trigger function** (returns `trigger`) so PostgREST won't actually let anon invoke it via `/rest/v1/rpc/` even though the advisor flagged it; verify, then consider revoking EXECUTE from anon for clarity.

**Action — `pack_grail_metrics_mv` exposed.** Materialized views in PostgREST API schema bypass RLS. If the contents are non-sensitive aggregates, fine; otherwise move to a private schema or wrap behind a SECDEF RPC.

### 2.5 Content Security Policy

`next.config.ts` ships:

```
script-src 'self' 'unsafe-inline' 'unsafe-eval'
img-src 'self' data: blob: https: http:
connect-src 'self' https: wss:
```

`'unsafe-inline'` + `'unsafe-eval'` together make CSP essentially advisory for script defense — XSS payloads can execute. `img-src http:` allows mixed-content image loads. Tighten when feasible:

- Use a CSP nonce in `next.config.ts` `headers()` (Next.js 16 supports nonce injection via middleware) and remove `unsafe-inline`.
- `'unsafe-eval'` is required by some libs (FCL, Three.js) — wrap behind nonce/hash if possible, or accept and document.
