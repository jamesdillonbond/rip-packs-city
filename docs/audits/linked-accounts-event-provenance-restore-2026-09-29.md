# linked_accounts — event provenance restore (2026-09-29)

**What happened.** The 2026-09-29 child-side run of `hybrid-custody-backfill` wrote
`record_link_state(..., p_event_block => NULL, p_source => 'script')` on 36 pairs that
already had `source='event'` rows. `record_link_state` treated a NULL block as newest,
so it set `last_event_block` and `last_event_tx` to NULL and `last_event_at` to the probe
time. Fixed forward in migration `20260929235500` (last_event_* change only on an event).

**How the values were recovered.** Dune was unavailable (the MCP account is read-only).
`first_linked_at` survives (it is never overwritten) and, for an event row, is the time
the ingester wrote the link, which runs every 20 min. For each pair: map `first_linked_at`
to a block height, scan Flow REST `/v1/events?type=A.d8a7e05a7ac670c0.HybridCustody.AccountUpdated`
over [first_linked_at − 4 h, first_linked_at + 15 min], keep events whose (parent, child)
match, take the highest block. **36 / 36 found.** Every event lies 0–19.4 min before its
row's `first_linked_at` (the ingester cadence). Every latest event is `active=true`,
matching the rows. Two pairs had several events in the window (0x6b24… 4, 0x1369… 3);
the latest was used.

**Limit.** An event for the same pair AFTER the window is not seen, so for such a pair
the restored `last_event_*` would be older than the true latest. Before the damage the
ingester would have written that later event, and we cannot tell whether one existed.

**Applied** 2026-09-29 ~5:40 PM PT via `execute_sql`; `RETURNING` listed 36 rows. After:
0 of 211 event rows have NULL `last_event_block` / `last_event_tx` (36 before).

**Revert** (restores the damaged state; there is no reason to):
`UPDATE linked_accounts SET last_event_block=NULL, last_event_tx=NULL WHERE source='event' AND last_event_tx IN (<the 36 tx ids below>);`
