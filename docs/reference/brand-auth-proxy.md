## Brand system

- `app/rpc-tokens.css` owns all tokens.
- `var(--rpc-red)` = `#E03A2F`.
- Fonts: `var(--font-display)` = Barlow Condensed, `var(--font-mono)` = Share Tech Mono.
- RULE: never hardcode `#E03A2F` or `'Barlow Condensed'` literals — always use tokens.
- Exception: `ConsoleGreeting.tsx` console `%c` only.
- ⚠ **THERE ARE TWO ACCENT REDS AND THEY ARE NOT INTERCHANGEABLE. Web is `#E03A2F` (`--rpc-red`, and `--por-red` is the SAME value). Email is `#E55A4C`** — rgb(229,90,76), visibly different — and it is hardcoded **on purpose** in email HTML (`lib/emails/**`, `lib/alerts/format.ts`, the alert/subscribe API routes), because **email clients do not support CSS custom properties at all**, so `var(--rpc-red)` there renders as nothing. `__tests__/welcome-email.test.ts` pins it. **So `#E55A4C` is correct in email and wrong on any rendered web surface**, where the token exists.
- ⚠ **The brand guard was structurally blind to the worse half of this until 2026-08-16: `LITERAL` matches `#E03A2F`, i.e. hardcoding the CORRECT red.** Hardcoding the WRONG red passed silently — untokenized *and* off-brand. It shipped on `app/auth/confirm/page.tsx`, the magic-link landing (spinner + message, 3 sites) and on `app/login/page.tsx`, while `login` used `var(--por-red)` for the same role a few lines away. `scripts/check-brand-tokens.mjs` now bans the email accent on web surfaces; it **walks `app/**` + `components/**`** rather than iterating `PROTECTED`, because a guard keyed to a curated list is silent about every file off it. ⚠ **Do not "simplify" it into a blanket ban on the literal** — measured, that fires on all 7 legitimate email uses.
- ⚠ **`--rpc-black` is THEME-AWARE (`#080808` dark, `#FFFFFF` under `[data-theme="light"]`), as is `--rpc-text-primary`.** So a hardcoded dark hex is not merely untokenized, it renders a **black slab in light mode** — the `SupportChat` defect, met again on `/auth/confirm` (`#0a0a0a`/`#fafafa`). The light-mode half is a SEPARATE list in the guard (`NEUTRAL_PROTECTED`) from the brand half (`PROTECTED`); a file can be in one and not the other, so check both before calling a surface clean.
- ⚠ **The auth funnel (`login`, `early-access`, `auth/confirm`) was invisible to the client-page ratchets until the directive detector was fixed** (see the ratchet bullet under Testing), which is why it had never been swept. It is now in `PROTECTED`. Its failed-read handling was checked at the same time and is **CLEAN** — recorded so nobody re-sweeps it: `sendMagicLink` sets `notOnAllowList` only on a precise `403 + reason=not_on_allow_list`, so a network error, a 5xx and a non-JSON body all fall through to a generic "temporarily unavailable" — **an outage cannot tell a real user they are on the waitlist.**

## The proxy's public boundary is per (path, METHOD) — a POST under a GET-only prefix 401s every signed-out reader (2026-09-25, PT)

`proxy.ts` `isPublicPath(pathname, method)` opens `/api/entity/*` to anonymous readers for **GET/HEAD only** (every route there is a read). The player-page Badge filter's route first shipped as `POST /api/entity/edition-badges`: production logged **3 of 3 live calls answered 401 by `serverless-middleware`** (the proxy's anonymous-fetch branch, `sec-fetch-dest: empty` → 401 JSON), so every signed-out visitor got "Couldn't load badges" and no filter. A signed-in allow-listed reader passes the session gate and never sees it, and every test was green: route tests call the handler directly and component tests mock `fetch`, so **nothing in the suite goes through the proxy**.

- **Fix shipped:** the route became a GET (`?collection=&slugs=a,b,c`, batches of 100). No proxy change was needed, and none was wanted — widening a method on a public prefix is a boundary change.
- **Pins:** `__tests__/proxy-is-public-path.test.ts` rows (GET public, POST gated), a route test that no `POST` is exported, and a component test that the grid calls GET.
- **The check that caught it:** Vercel runtime logs grouped by status for the new path (`get_runtime_logs`, `query: "<path>"`, `group_by: "statusCode"`). Your own session cannot see it — you are signed in.
- ⚠ **Rule:** a client fetch from a PUBLIC page must use a method `isPublicPath` opens for that path. Read the proxy row before choosing POST for a read.

## Security rules from the 2026-10-25 audit (register R133–R142, PT)

Each rule below is enforced by a test; the test names are the place to read the cases.

- **Admin credentials.** Every check of `RPC_ADMIN_TOKEN` goes through `lib/admin-auth.ts` `verifyAdminRequest` or `lib/auth/bearer-secret.ts` `bearerMatches` / `tokenMatches` by NAME — no route reads the env var itself (`admin-token-compared-only-in-shared-helpers.test.ts`, allow-list with reasons). Browsers store a **12 h HMAC session** (`lib/admin-session.ts`, `rpcadm1.<exp>.<sig>`, minted by `POST /api/admin/session` from the master token only; rotating the master token kills every session), never the master token — including the shared hook `lib/admin/use-admin-resource.ts` (`admin-resource-hook-stores-session.test.tsx` bans any writer of the admin storage key that skips the exchange). Scripts and cron-job.org keep sending the master token. `?token=` query auth is being retired (R133, logging since 10-25; decision 2026-11-01).
- **"Saved" is not "owned".** Anyone can save any address. A privileged or private per-wallet action (MCP keys, billing portal, anything keyed by a wallet's plan or money) must call `requireOwnedKey(wallet)` (verified saver, else first saver — #176), never a `saved_wallets` membership check. Membership is fine only for public on-chain reads (#59).
- **Third-party bytes from our origin.** Every `MEDIA_PROXY_PREFIXES` path gets `MEDIA_PROXY_CSP` (`default-src 'none'; … sandbox`, no script source) from `proxy.ts`, so a document opened from one cannot run script; and a proxy whose upstream is caller-chosen (`/api/public/ipfs-media`) streams only `lib/media/servable-media-type.ts` types (raster image / video), redirecting anything else to the gateway. A new media proxy goes in `MEDIA_PROXY_PREFIXES`. Never serve SVG/HTML/XML from a caller-chosen source same-origin.
- **Inline JSON in a `<script>`** goes through `lib/seo/json-ld-script.ts` `jsonLdScript()` — bare `JSON.stringify` does not escape `</script>` (`json-ld-is-script-safe.test.ts`, ban at zero).
- **CSP:** `script-src 'self' 'unsafe-inline'` — `'unsafe-eval'` dropped 10-25 after measurement (R135); `'unsafe-inline'` stays because only a nonce removes it and a nonce forces dynamic rendering. `connect-src` lists only hosts a BROWSER calls (server-only workers are not in it).
- **Workers:** every Cloudflare worker fails closed on its secret, compares it with a local constant-time `safeEqual` (`workers-compare-secrets-in-constant-time.test.ts`), and never fetches a caller-chosen host. dune-proxy runs only RPC's own query ids; helius-proxy forwards only read-only DAS methods. Workers are deployed from Trevor's machine with `node scripts/deploy-workers.mjs` (no Cloudflare credential exists in GHA or the cloud sandbox).
- **MCP quota** is check-and-count in one transaction: `mcp_reserve_tool_call` (per-wallet advisory lock) before each tool call; `mcp_log_tool_detail` for the per-tool row (pin `supabase/tests/mcp_reserve_tool_call.sql`).
- **Deployment Protection** is Vercel Standard (`prod_deployment_urls_and_all_previews`): old deployment and preview URLs 302 to Vercel SSO; `www` is unaffected and pipeline self-chaining uses `chainBaseUrl()` (production → `https://www.rippackscity.com`).
- **Known residuals, by decision:** `pg_net` is EXECUTE-able by anon/authenticated as a platform default `postgres` cannot revoke (R136 — the control is that no anon-callable function touches `net`; re-probe query in the register); 6 deployed-only `verify_jwt:false` edge functions have no repo source (R137).
