# Rip Packs City — Roadmap (2026-07-20)

Supersedes `roadmap-2026-07-18.md`. That plan's Phases 2–3 are substantially done; this one records what changed and what the gate actually is now.

## Where things stand

**Go-live: done and verified.** Public un-gate live since 07-17. IA reorg, Market=edition / Sniper=serial, Packs and Moments sub-tabs all shipped and browser-verified.

**The data layer got materially more honest (07-18 → 07-20).** This was not on the last roadmap and turned out to be necessary: the Moments → Sold tab was showing a founder wallet **7 sales when the truth was 38**. Root cause was not a display bug — `sales` carried buyer/seller for only ~21% of Top Shot rows, because the bulk of history came from studio-platform imports that never included wallet addresses.

Shipped in response, all running unattended:

| system | state |
|---|---|
| `sales-counterparty-backfill` (CF worker, free tier) | **203k+ recovered**, ~34.5k rows/day, multi-collection, no Dune dependency |
| Dune seller-recovery + sales-ingest | armed, **parked on the datapoint cap** — see below |
| impossible-parallel self-heal (pg_cron `:52`) | retires 7 waves of manual toil; monotonic, audited, idempotent |
| lock freshness | on-view refresh fixed + batch reliable since the 120s timeout fix; AllDay now stamps `lock_checked_at` |
| CI status watch (`ops-monitor`) | closes a gap where `main` sat red ~24h undetected |
| funnel instrumentation | `collection_view` added; landing → collection → Market/Sniper now measurable |

**Dune is capped by decision.** Both Dune pipelines hit the per-billing-cycle **datapoint** limit (not credits — see [[dune-datapoints-not-credits]]). Plan will not be upgraded. Dune is an accelerator with a hard ceiling; the free Flow-REST worker is the sustainable engine. Both pipelines fail safely and auto-resume on reset.

## The gate has not changed: traction

The funnel now measures honestly, and it says **31 sessions / 7 days, 1 outbound click, 0 email signups**. The platform is in good shape for a user base of roughly one person.

**That is the whole roadmap.** More data correctness, more backfill throughput, and more infrastructure do not move it. The bar remains **50+ WAU** before monetization is discussed.

### Phase 1 — get the first cohort in (the only phase that matters)

1. **Panini go-live.** Gate is met — the runner is live and flowing (1,363 of 1,370 editions refreshed <24h). Go-live is deleting **one `proxy.ts` line** (~L127) plus sitemap/hub links. It is genuinely differentiated data nobody else publishes, and the kind of thing that gets shared. Highest-leverage distribution asset currently sitting behind a one-line change.
2. **Distribution.** Trevor's call on channel and timing; no promo until he says. The instrumentation to tell whether it worked is now in place and verified, which was not true before 07-19.
3. **Read the funnel weekly.** `funnel_events` + `outbound_clicks`. Landing → collection → Market/Sniper drop-off is now visible.
4. **Watch concierge transcripts.** Real user questions remain the highest-signal roadmap input available.
5. **Real-device mobile pass** (operator). Residual is touch targets <44px and horizontal-scroll tables.

### Phase 2 — cost/latency (mostly done, one lever left)

- Seed-wallet cadence 12h gate live (~29 lambda-hrs/day, corrected down from an initial ~56 estimate).
- **Open:** the non-wave `wallet-backfill` driver — ~2,253 runs/day at hours nobody schedules (5/10/15/16/21 UTC). cron-job.org, GHA, pg_cron and Vercel crons are all ruled out; `lib/allow-list/prewarm.ts` (calls with `?force=true`, bypassing `skip_cached`) is the lead. This is now the biggest remaining cost item.
- Optional housekeeping: make the 12h cadence permanent in cron-job.org and delete the in-route gate.

### Phase 3 — durable debt (opportunistic)

- **`sales` ingest gap** — measured, era-concentrated: pre-2026 TS is **18–27% covered**, 2026 is 61–74%. Scope any fix to pre-2026 Top Shot only. **Dedup on `(tx_hash, nft_id)`, never date proximity** — 634 pre-2026 acquisitions have a sale row outside a ±2-day window. Blocked on Dune capacity that will not be bought; the free worker chips at it instead.
- **`MAX_AGE_DAYS`** — now documented as a background target (7-day re-check needs ~226k checks/day; batch delivers ~19,200). Raising the value is a real eligibility trade-off, still an owner call.
- **Market dead links** — needs a numeric TS edition flowID we do not store and the public API will not expose (`Edition.flowID` absent, persisted-query allowlist). Needs a browser-harvest lane or acceptance of "—".
- Profile route consolidation; mobile polish; monolith refactors when a feature forces them.

### Phase 4 — chain two (readiness-gated, parallel allowed)

- **Candy/Solana** — Drop 1 ingested (125 editions, 25,375 serials); `is_active=false` until the surface is quality-bar clean. Blocker remains zero price signal.
- **Panini** — see Phase 1. Coverage is listing-gated (~46%) and that disclosure is now built structurally into the surface.
- **Beezie/Base** — parked, no product consumer.

## Standing guardrails

- No paywall/Stripe/public push until **50+ WAU**.
- No infra spend pre-revenue — levers first. (Dune plan explicitly not upgraded.)
- Direct-to-`main`, no branches/PRs. Ledger entry with a revert path for anything touching `main` or prod.
- **Ledger discipline:** re-read from disk immediately before writing, splice your entry into the fresh file, and assert the `^### ` count went UP. A stale whole-file write silently destroys other sessions' revert paths — nearly happened again on 07-19 (would have dropped 16 entries).
- Verify pages by **rendered DOM, not HTTP 200**; streaming shells always return 200, and a mid-load screenshot is not a bug report.
- `wrangler deploy` publishes **local** files — `git pull`, then grep the source for your change before trusting a deploy.
- An **empty commit cannot force a Vercel rebuild** here (`ignoreCommand` skips it). Touch a real file.

## Method note

Roughly half the value of the 07-18→20 push came from measurements that **overturned a premise** rather than from code: the hydration view needed no trigger queue (an optimizer fence, not selectivity); lock counts *overstate* rather than understate; "scope to viewable wallets" was not a lever (the whales *are* the seeded wallets); raising `BATCH_LIMIT` was unsafe (cron-job.org's 30s cap, not the route budget); and circ-99 was a real print-run tier, not a bad default.

Check before building, and re-check before asserting. Several of those, unchecked, would have sent a full session in the wrong direction.
